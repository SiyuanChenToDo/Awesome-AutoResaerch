# 自主猜想运行的可靠性修复

2026-10-19。针对真实无人干预验收发现的失败修复框架；不改写上一轮候选、报告、分数或审计。默认四研究者、两轮讨论、ARIS 七维权重和模型配置保持原有设置。

## 新运行如何使用

原有 `python -m sage autonomous --allow-live --output ...` 入口自动启用新协议和互评审计，无需人工拼接产物。研究者用 `protocol_schema` 取得协议与修订记录格式；slot 0 用 `report` 从当前已登记主稿生成 `CONJECTURES.md`，修改主稿后重新生成。正式评阅只接收最新登记版本，并保留两次协调者 advisory 的原有门禁。

只在旧嵌入式调用中保留 `require_protocol=False`、`enable_peer_audit=False` 的兼容开关；证据文件明确记录 `legacy_unverified`，不能将旧报告追认成新协议验证。默认 native runner 显式打开两项。证据卡完整审计留在私有服务，给模型的传输视图只移除重复账本，不移除逐条未知/不支持状态。

launcher 身份由入口自动写入受保护的 `launch.json` 并交给 manager，无需额外用户配置。父进程失活时，`runtime-crash.json` 先保存停止意图，再记录已核验的依赖进程清理与 manager 退出请求；`manager_exit_observed=false` 保持明确，进程不能证明自己最终已经退出。确认 launcher 已丢失且没有既有终态时，只创建 `workflow_status=incomplete` 的失败结果，无法重建的实际评分次数与科学分数为 `null`。身份只是暂时不可核验时不抢写 launcher 的结果，但正常收尾也必须把该故障作为未完成。历史有效评分与原始科研数据不改写。

守卫最多每秒检查父进程身份，清理使用既有有界 TERM/KILL 机制；启动与身份登记同锁，协调者和 worker 都受控。已经发到服务端的调用仍可能完成或计费，断连只能保留远端结果未知。此保护针对 launcher 丢失而 manager 仍存活；整个容器或两者同时硬退出时，进程内守卫不能运行。manager 存活、请求退出和观察器确认全空是三个不同事实。

## 验证范围

`python scripts/check.py` 检查离线契约、故障恢复、真实本地子进程/HTTP 生命周期以及确定性导出。它不调用付费模型，也不证明猜想新颖、实验有效或可投稿。独立 Linux 检查与部署的准确版本和结果保存在本地修复记录中。

旧正式报告已只读重放核验；历史错误报告被新检查阻断，不对历史数据补写字段。新系统仍须在新的无人干预运行中评估科学质量、成本、跨模型独立评审和真实实验，不能把修复回归测试称作这些验收已经通过。
