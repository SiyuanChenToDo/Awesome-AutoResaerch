# 第二位学生修订失败的离线诊断审查

## 已确认的证据缺口

上一轮有界真实回归新增 10 次 DeepSeek 调用、0 次检索，输入 94819、输出 8867、合计 103686 SDK tokens。完整 discussion 在第二位学生修订阶段失败；独立计划的通过不是 end-to-end 成功。本轮工程诊断新增真实调用 0。

检查 real-regression-01 的 result、audit、checkpoint 后确认：最后失败 entry 只有 status=failed、error_code=invalid_response，没有 value/raw_response/validation 细分；此前格式没有 rejections 集合。审计仅保存三个修订失败事件的 stage/attempt/code。第一位学生首次失败后第二次通过；第二位连续两次失败。不能重放缺失的原文，不能断言失败来自原文保持、来源越界或 JSON 字段中的某一项。

因此本次没有声称复现该真实回复，也没有伪造一条“原始失败回复”当回归样本。测试区分实际观察到的缺诊断元数据形状与人为构造的受控违规回复；后者只能检验规则与诊断机制。

## 正式修复

- errors.py：添加白名单规则/字段诊断，仍继承 InvalidResponse。消息只来自程序定义，不回显任意模型值或未知键。
- discussion/__init__.py：各规则抛出对应字段/规则；抽出纯函数 validate_revision，可离线重新运行完整修订规则，不改写传入对象。
- runtime.py：保存字段级原因、stage、attempt、响应哈希/长度；有限重试把准确预定义反馈加入下一次请求。保持相同模型/输出上限/总预算，不自动变更输出、不接纳失败或未知意见。终态保留具体原因，检查点失败重放也保留诊断。
- checkpoints.py、cli.py：显式 retain-rejected-responses 可保留有大小上限的私有请求/回复用于后续重放；默认关闭，原文不进入审计。记录不是成功缓存，不会被自动采纳，权限 0600。
- discussion/context.py、prompts.py：修正一个独立发现的提示歧义。此前修订输入的可引用集合包含所有 supported 意见的来源，但验证器只允许实际采纳意见的来源。现在无条件清单只含自身及先前已采纳来源，新增来源按 critique_id 列在条件表中，明确只有接受该意见才授权。验证器未放宽。这是经代码对照确认的提示/规则不一致，**不是已经证实的历史失败原因**。

## 回归验证的含义

受控测试覆盖原文变动拒绝、未知意见不可采纳、条件来源不可提前引用、字段级原因相互区分、重复 JSON 键、敏感标记不进入日志/反馈、有限反馈重试、两次持续违规仍失败，以及可选私有原文保存后离线重放得出相同规则。原有 adversarial 来源/采纳/多轮保留测试继续运行。该离线诊断阶段没有真实模型复测；后续定点验证见下节。

## 结构化计划的一次局部修正

有界真实回归的第 9 次调用是一份独立计划，不是完整 discussion 后的输出。它通过当时的 JSON schema，但本地审查发现：

1. budget.cap 写 UNRESOLVED，budget.status 却是 proposed。
2. 将本轮新提案名称 BM-GATE 当作已有实现，提出需要访问其实现。
3. plan_contract 标签嵌入 experiment 正文。

第 10 次调用继续使用正式 ExperimentDesign.plan_response、同一模型、同一 3000 输出 token 上限和共享 12 次总预算，仅添加明确的局部审查指令：BM-GATE 是本轮新候选；缺预算决定必须 unresolved；不要编数字；experiment 必须先闭合再输出 plan_contract。第二份实际回复修复了这三项：预算单位/上限和状态均 unresolved，不再假设已有 BM-GATE 实现，两个标签不嵌套。首次输出未删除。

这不是自动后处理，不是通过篡改输出得到成功，也不是已经证明基础提示稳定可靠。当前计划 schema 仍不足以自动验证所有跨字段语义或科学设计；本轮没有把这次人工式审查提示包装成普遍科学验证。样本量/停止规则仍 unresolved，execution_ready=false。
