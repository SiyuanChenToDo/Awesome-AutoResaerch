# SAGE 真实故障工程修复审查

本页记录此前真实 arXiv/DeepSeek 运行暴露问题的正式代码修复。此次工程阶段只运行离线测试，没有新增付费模型或文献请求；不把旧版本真实运行当作新代码实测。

## 三项优先修复

| 问题与根因 | 正式代码 | 回归断言 | 尚未验证 |
|---|---|---|---|
| 角色来源越界：提示同时显示自己和目标的证据，笼统“supplied IDs”不明确所有权 | discussion/context.py、discussion/prompts.py；原 discussion/__init__.py 验证不放宽 | 提示明确 own 可引用/peer 不可引用；即便 peer 可见仍抛 InvalidResponse；原恶意来源测试保留 | 真实模型遵从率；引用内容是否语义支持意见 |
| 综合提示超过 100k：学生原稿、发展稿、历史修订与当前候选重复嵌套，交接卡片也重复 | discussion/context.py、orchestration/__init__.py | 大于100k的历史样例压缩至限额内；完整证据逐项还原；当前想法、原文采纳要求/来源边保持；超长核心证据仍拒绝发送 | 更大真实文献池、复杂多轮模型质量 |
| 规划两次 length 截断：原重试重复同一长输出请求 | providers.py、errors.py、runtime.py、experiment_design/contract.py 与 __init__.py | 截断单独分类；下一次提示变简洁且 cap 不变；两次截断后失败，不返回部分文本；计划缺预算/指标/样本字段或伪称执行批准被拒绝 | DeepSeek 新提示的成功率、完整性、科学设计合理性 |

这些修复不是通过删除校验、扩宽可引用集合、自动采纳意见或接受部分文本完成。失效/未知意见仍不得采纳，修订无采纳时仍须原文不变。摘要缺失的实验细节仍未知。

## 检查点与缓存

正式文件 checkpoints.py、runtime.py、cli.py、discovery/__init__.py 实现原子 JSON 检查点及精确输入重放。代码、输入、提供方、限制有哈希身份；研究内容私有保存，绝不保存模型密钥/代理配置。成功请求先落盘再继续下游；没有把 result.json 当成任意可执行快照。通过原控制器重建产物，成功步骤缓存命中不发请求并重新验证；预算与失败保留。阶段参数变化不会误用缓存。

显式 allow-incomplete-novelty 可将临时筛查不可用标为未知，补充规划检索不可用也有记录；锚点/链长/独有来源及拒绝性错误门控不变。精确 cache-only 不支持把新查询映射成“旧池里随便找几篇”的成功检索。429 保留 Retry-After 并停止此谱系的新论文请求；未新增无限退避或网络绕过。

限制：运行期间只允许一个写入者；检查点是本地可信文件，不是防恶意修改证明。断电/远端已计费但本地未记录仍有歧义，默认拒绝重复，显式 retry-uncertain 才能重试。版本或配置不一致拒绝恢复；旧临时脚本没有自动迁移。活跃墙钟预算延续，进程间停机时间不计。正式恢复只覆盖提案 run，不覆盖有副作用的 laboratory 执行。

## 规划结构及科研问题

新增 plan_contract 明确区分 proposed/unresolved；n 可以未知，但不能伪装为已冻结或已测量。每次修订都重新校验结构。它不计算公式、不证明预算匹配、不作功效分析、不判断文献支持、不替代实验合同。此前可读计划中的计费双计、precision 定义、统计功效等问题并未通过本次软件改动被科学解决；新增结构是使问题显式可审查，而非自动背书。

## laboratory 的实际架构缺口

当前 EvaluationContract 固定 `features: tuple[float]`、`targets: tuple[float]`、development split、MSE 指标和最小损失选择；ExecutionBackend.predict 输出一个数值列表。本文研究对象需要 `(idea_id, premise_id, claim, passage_ids, support_label, abstention, costs)` 及来源语料快照，不能编码成一组标量 MSE 后宣称完成原研究。

具体不兼容：

- 输入不是标量向量，而是冻结前提、文本片段、文献版本和实验臂；当前模板没有这些数据入口。
- 输出不是连续预测，而是引用定位、验证/弃答标签和可核对的调用成本事件。
- 独立评价需要冻结蕴含/支持判定规则、人工或独立判定标签与保管边界；MSE 无法表达引用真实性、支持率、coverage 和错误核验率。
- 匹配预算需要共享计费账本和失败/重试计入，当前合同只有 attempt/time 上限，无法保证各臂资源等价。
- 统计应按 idea 聚类/配对，需预设样本量、多指标方向和择优规则；当前 attempt_budget_or_zero_loss 不适用。
- 已有报告器依赖 scalar execution 记录和数值指标，不能在没有领域评价证据时生成通用“实验报告”。

## 最小扩展方案 待决定 未实现

1. 定义版本化 `EvidenceEvaluationContract`，保持 scalar 合同原样：冻结 corpus/claim/split manifests 及 SHA256、许可证、臂定义、成本单位/权重/上限、样本计划、指标定义和停止规则。冻结标签及评分逻辑由宿主可信评价器保管，候选不可修改。
2. 新增可判别的输入/输出协议和后端方法 `evaluate_evidence`，仅返回带 source ID、claim ID、标签和成本事件的结构化候选结果；保留精确合同 digest 授权和已有安全边界，不接受 arbitrary evaluator code。优先离线冻结语料，外联与实际模型预算另行显式授权。
3. 独立实现并测试来源 ID/片段偏移校验、预定义支持标签比较、精确率/错误比例/覆盖率及成本聚合；蕴含真值、双判定冲突处理和人工标注协议必须先决定。API成本是否可独立核对也需定义，不能只信候选自报。
4. 扩展 runner 按合同类型分派，冻结择优与停止逻辑；用最小真实授权数据做受控端到端验证，绝不拿 fixture/toy替代主题研究。代码生成、执行和报告分别记录状态与失败。
5. 增加 `--proposal` 的受审查提案交接入口，验证来源、合同适配和预算谱系；目前本轮仅提案检查点，尚不能将历史 result.json直接交给 laboratory 并安全跳过提案生成。
6. 扩展报告 schema，让每个定量声明链接到冻结指标/原始日志；保留 failed/unknown 和未执行状态。上述接口、数据、成本和评分定义需要研究负责人决定后实现，本次不启动实验。

原任务的代码生成、真实执行、独立评价、反馈迭代和报告阶段仍未完成。以上工程修复使提案运行更可恢复、更可审计，不代表完整 AgentLab 实验已跑通。
