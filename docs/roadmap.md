# 路线图：先可靠记录，再受限执行

这是按验收条件推进的计划，不是交付日期承诺。功能的“已实现”仅指仓库内可检查的文件/脚本；外部论文或工具的存在不等于已接入。

## P0：可搬走的研究包（本仓库起点）

范围：中文工作流与架构、文献/假设/计划/声明/复盘模板、离线计划示例、资源目录和根目录 README 列明的初始化/检查工具。

验收：

- 新研究项目可从模板建立，未知值仍为未知，不生成假实验记录。
- JSON 与本地链接可检查；不需要 API 密钥、GPU 或付费服务。
- 来源和核验状态可区分；模板不把引用当事实证明。
- 文档明确区分已提供的脚手架与后续执行能力。
- 人工能够走完一次“不支持假设”的报告，负结果不被流程淘汰。

**边界**：检查文件存在和字段有效不等于计划科学有效，也不等于审批可信。P0 不运行训练、不启动无人值守循环、不承诺自动审稿或可发表性。

## P1：一个低风险本地执行适配器（待实现）

范围：仅批准代码、离线合成数据、固定入口和资源上限；一次只做一个明确实验。先实现本地受限执行，再考虑多 Agent。

验收：

- 检查批准的计划身份和哈希；预算可计量、可中断。
- 真实的路径/网络/进程隔离，保护评分器与测试数据。
- 每次尝试有状态、原始日志、消耗、制品和内容校验和。
- 幂等提交、失败保留、恢复不重复启动、取消可确认。
- 注入、路径越界、评分器修改、超额预算等负向测试通过。

**不得扩大为**任意命令 runner。不能直接执行论文、网页或检索内容里的代码。

## P2：独立评价与可信证据账本（待实现）

范围：独立权限域的最终测试、严格数据/代码身份、追加式事件记录、派生报告重建、完整性审计。

验收：

- 开发者不能读取最终标签或改写评分器；访问次数可审计。
- 并发写入不丢记录；崩溃后可恢复且不伪造完成状态。
- 原始记录更正有来源与历史；备份/恢复与篡改检测有测试。
- 从原始结果重建全部图表、区间和声明链接。
- 报告泄漏、缺失或失败时不会被默认当作有效低分。

## P3：可替换的研究能力接入（待实现）

范围：先接一个文献检索器、一个想法生成器、一个受限实验后端；再依据实际需要扩展。模型、工具和供应商不进入核心文件格式。

验收：

- 适配器输入输出符合[契约](architecture.md)，固定版本、成本和错误语义。
- 相同项目迁移后，ID、证据链、失败记录与数据边界不丢失。
- 以强且简单的基线比较增益，同时记录人工修正量与费用。
- 外部系统的授权、许可、依赖和风险已独立审查。
- 想法质量、执行成功、科学效果分别评价，避免把系统接通当研究成功。

## P4：证据约束的策略改进（待实现）

范围：从已审计的运行中提出流程/提示词/搜索策略改进；独立开发任务选择策略，新的未见任务验证迁移。

验收：

- 对每条经验执行采纳门槛，保留反例、适用范围和退役路径。
- 改进建议不能自行扩大权限或改变本轮评价标准。
- 比较固定策略、简单启发式和新策略；计算全部策略搜索费用。
- 跨任务证据支持后才扩大主张；重复使用同一任务不算独立迁移。

## 选择下一步的规则

优先修复“证据会丢”“失败被藏”“无法重算”“边界没守住”的问题，其次增加自动化覆盖，最后再追求吞吐量。只有一个已审查的低成本实验真正闭环后，才值得引入调度器、远端 GPU、可视化控制台或大规模多 Agent。

每一阶段都允许停止：如果人工流程已解决问题，就无需为自动化而增加一个难以审计的系统。
