# 基准选择：先明确能力，再决定分数

基准是测量工具，不是研究问题本身。选一个容易接入或分数漂亮的任务，可能无法检验核心假设。填写[基准选择卡](../templates/project/benchmark.md)，再冻结[实验协议](../templates/project/preregistration.json)。

## 1. 先区分你在测什么

| 研究目标 | 最小评价单位 | 关键对照 | 特别容易误判的地方 |
|---|---|---|---|
| 文献检索与综合 | 可定位的证据问题/声明 | 普通检索、简单 RAG、人类抽样复核 | 有引用不等于引用支持结论；检索不到不等于不存在 |
| 想法与假设生成 | 有边界、可证伪的研究提案 | 简单重组/单 Agent/专家盲评 | 新颖、可行与有效是不同维度；漂亮提案未必可执行 |
| 论文复现 | 论文贡献拆解后的任务/实验 | 原实现或官方复现协议 | 代码能运行不等于论文结论被复现 |
| ML 工程或优化 | 固定任务与预算的一次完整尝试 | 强且简单的搜索/优化基线 | 搜索预算不公平；把开发集最好值当泛化效果 |
| 新方法的科学效果 | 独立任务/数据集/种子下的比较 | 已知强方法、成本匹配、组件消融 | 单基准改进不足以证明机制、原创性或广泛适用 |
| 端到端研究 Agent | 从问题到证据包的完整研究运行 | 相同工具/预算下的受限流程 | 只评论文外观，忽略过程、失败与不成立的声明 |

这一分类是本仓库的设计建议，不是声称存在一个通用科研能力总分。

## 2. 可核验的候选入口

以下能力描述依据 2026-10-17 读取的一手论文摘要。只核对用途，**未下载任务、未审计许可、未运行基准，也不引用当前排行榜**。正式选用前仍需核查官方代码、数据版本和运行要求。

| 候选 | 一手定义支持的用途 | 本仓库建议的使用边界 |
|---|---|---|
| [PaperBench](https://arxiv.org/abs/2504.01848v3) | 以 AI 论文从零复现为任务，使用分层 rubric 拆解贡献 | 适合代码/实验复现能力；不能直接证明研究新意。若使用自动裁判，独立检查评分质量 |
| [MLE-bench](https://arxiv.org/abs/2410.07095v6) | 以 Kaggle 竞赛任务评价数据准备、训练和实验等 ML 工程能力 | 适合固定任务的工程流程；要核查预训练污染、数据条款与预算公平 |
| [CORE-Bench](https://arxiv.org/abs/2409.11363v2) | 利用已有代码与数据重现论文结果，覆盖多学科的计算可复现性 | 适合环境与结果复现；不能把复现能力等同原创发现 |
| [LitQA2 / PaperQA2 论文](https://arxiv.org/abs/2409.13740v2) | 文献研究中的信息查找、综合与矛盾识别评价，提出 LitQA2 | 适合文献阶段；不替代实验结果或因果验证 |

清单中较新的条目可进入候选池，但在核对标题、版本、任务资产、许可和评价协议前，只算线索。来源中的历史成绩、热度、融资或“首次”描述都不能用作接入优先级的充分证据。

## 3. 选择方法

先设硬门槛，再对通过者评分。下面的权重只是起点，应在看到系统表现前按研究目标调整。

**硬门槛**：任务与主张相关；数据/代码可合法取得；所需资源在预算内；评价器可固定；存在合适的开发/测试分离；没有无法接受的安全或隐私风险。任一不满足就排除或标记阻塞。

**评分建议**：问题匹配 30%、评价可审计性 25%、污染可控性 20%、成本与运行可行性 15%、多样性与失败覆盖 10%。每项 0–2 分，并附证据；总分只用于排序，不能盖过硬门槛。

至少比较一个低成本起步任务和一个更接近真实研究的任务。先做最小接入验证，再扩大任务集；不要因为某个任务失败而事后删掉它。

## 4. 冻结实验边界

- **版本**：论文版本、基准提交、数据哈希、评分器和依赖版本均固定。
- **抽样**：预先列出任务 ID、难度/领域分层和排除原因。小规模子集报告为子集结果，不与官方全量分数直接等同。
- **可见信息**：明确各方法是否能读目标论文、原代码、公开答案、互联网、历史实验或测试标签。
- **污染**：记录公开任务及解答可能进入模型训练的风险；按时间切分并不自动消除污染。无法核验时保留限制。
- **预算**：相同的总 GPU 秒、费用或明确的多资源约束；同样计算检索、调参、重试、并发和失败成本。
- **测试访问**：开发结果用于选择，最终测试仅在候选冻结后按协议访问。超额访问是偏离，不是免费再试。
- **裁判**：优先使用固定、可复算的指标；需要人工/模型裁判时固定 rubric、盲化系统身份、记录裁判版本和一致性抽查。

## 5. 不只报告最终分数

至少并列四组指标，避免用加权总分遮住安全或科学失败：

1. **任务效果**：逐任务结果、汇总效应、不确定性、成功率及失败分母。
2. **资源效率**：总消耗、每个有效结果成本、重试、墙钟与算力。
3. **过程质量**：基线完成率、计划执行覆盖、负结果保留、断点恢复与复现率。
4. **证据完整性**：声明有直接支持的比例、引用核验、未授权边界变更、测试污染和无效实验。

证据完整性问题不是“扣几分即可抵消”：评分器篡改或测试泄漏会使相关科学结果失效，应隔离并调查。

## 6. 停在能力所能支持的位置

文献问答分数不能证明独立发现能力；论文复现不能证明方法新颖；在几个任务中优化成功不能证明长期自主科研可靠。若目标是端到端研究，需要同时审阅问题、计划、所有尝试、证据与最终声明，并公开“成功的研究运行”定义。

本仓库的[合成数据示例](../examples/toy-regularization/README.md)只用于练习计划与审计结构，不能作为真实研究能力基准，也没有已运行成绩。
