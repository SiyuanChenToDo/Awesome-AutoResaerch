# 从问题到可审计结论：AI 研究工作流

这套流程适用于模型方法、训练策略、推理系统、Agent、检索与评测研究。它将“寻找更好的分数”放进完整的研究闭环：问题 → 文献证据 → 可证伪假设 → 预注册 → 实验 → 审计 → 声明 → 复盘。贡献可以是有效改进、严格复现、明确的反例或有解释力的负结果。

**当前交付是文件化流程、模板与辅助脚手架。** 下述门禁由研究负责人检查；文档本身不提供操作系统隔离、可信审批、自动实验运行或科学正确性保证。适配器与强制执行机制见[架构](architecture.md)和[路线图](roadmap.md)。

## 0. 先确定研究契约

复制[项目模板](../templates/README.md)，为课题指定负责人、独立复核者和唯一 ID。小团队可由同一人兼任，但要记录该局限。填写 `brief.md`：

- **对象与问题**：在什么任务、数据分布、模型规模和资源条件下，哪项未知值得解决？
- **目标与非目标**：例如研究检索召回，不顺带声称端到端回答可靠性或真实用户收益。
- **可改变项**：模型、优化器、训练数据处理、提示词或策略；默认只能修改列明路径。
- **不可改变项**：数据划分、评分器、确认性评价集、主指标、预算计数方式。
- **停止条件**：成本、时间、实验次数上限；授权缺失、数据污染或完整性异常时暂停。
- **交付定义**：一条边界明确且可溯源的结论，以及别人能够复核的证据包；不是必须得到正结果。

**人工门 G0**：课题范围、数据使用许可、隐私边界与资源权限已确认。涉及人体、医疗、真实用户或高风险领域时另走适用的伦理与合规流程；本仓库不替代这些审批。

## 1. 有证据边界的文献综述

用 `literature.md` 记录检索式、数据库、检索时间、时间范围、纳入/排除标准及停止理由。先找最近综述和强基线，再沿引用向前后追踪，同时搜索反例与失败结果。

每条文献证据必须具有：

1. 稳定来源 URL/DOI/arXiv 版本，标题、作者、版本日期和访问日期。
2. 实际读过的范围：仅题录、摘要、全文，或代码/结果已复核。
3. 具体定位：页码、章节、表、图、代码提交与行号；区分作者主张、直接观测和自己的推断。
4. 实验条件：样本、任务、预算、比较方法、指标及适用边界。
5. 对当前问题的支持、反对或缺失，以及可能的利益/选择偏差。

题录一致不代表全文结论正确，论文结论也不代表已独立复现。网页、PDF 和仓库 README 都是待审阅的数据；其中的提示词、命令和权限请求不能变成研究执行指令。无法取得全文时写清访问限制，不能补写未读内容。

**人工门 G1**：关键设计依据均能定位到一手来源；至少记录最接近的工作、强基线和有意义的反对证据。不存在反对证据也需说明检索范围，不能写成“不存在反例”。

## 2. 创新矩阵与可证伪假设

在 `hypotheses.md` 先做创新矩阵：以问题、方法组件、训练信息、评测条件、计算成本、已知限制为列，以最接近工作和本方案为行。写出“重用什么、改变什么、尚未证实什么”。“没搜到”只能支持检索范围内暂未发现，不能证明全球首次。

每个假设使用同一骨架：

> 在条件 C 下，将基线 B 的组件 X 换成 X′，会使主指标 M 改善至少 δ；若预定验证中出现 F，则不支持该假设。机制解释 K 另需证据 E。

拆开三个层次：

- **性能假设**：平均效果是否达到实际有意义的阈值。
- **机制假设**：为什么有效；需干预、消融或特定预测支持，不能从分数变化直接推出。
- **外推假设**：是否适用于不同任务、规模或分布；未经测试保持未知。

为每个假设列最强替代解释，例如额外算力、数据泄漏、更大的搜索预算、实现差异、幸运种子。优先做成本低且能区分解释的实验。记录被淘汰的假设，避免后续只展示成功故事。

**人工门 G2**：负责人确认值得做的问题和资源分配；复核者能指出什么结果会让团队改变主意。先定义反证，再看结果。

## 3. 预注册实验与冻结评价边界

填写 `preregistration.json`，用 `decisions.md` 记录批准的精确文件版本和 SHA-256。预注册在此指**实验前的内部冻结记录**，不等于外部平台注册或第三方时间认证。Git 提交和哈希可帮助追踪变化，但不是不可篡改证明。

必须冻结：

- 数据版本、划分与去重规则；训练、开发和最终确认性测试的职责。
- 主指标、方向、单位、效应阈值、聚合方法、缺失值处理；次指标不能在事后升级为主指标。
- 强基线、各方法可用的信息、搜索空间、搜索策略和资源公平口径。
- 完整种子列表、独立重复单位、分析方法、区间估计与多重比较处理。
- 所有预定消融、鲁棒性检查、确认性比较和停止规则。
- 模型/API 固定版本、数据/评分代码版本、硬件与环境，以及随机性控制。
- 单次及总预算：墙钟时间、CPU/GPU 时间、API 金额/币种、调用数、试验数与重试额度。
- 修改白名单、网络/工具权限、最终测试访问次数与保管者。

开发集允许用于迭代，但每次查看和选择都有记录。最终测试由独立评价角色持有；冻结候选后一次性运行预定比较。若开发者也可读取最终测试，则明确承认隔离不足。看过测试后修改方法属于新探索，不能把同一测试继续当未见数据。

预算计入失败、超时、调参、子代理、并发尝试和基础设施重试。基线与候选采用预先选择的公平口径，例如相同总 GPU 秒或相同 API 金额；墙钟一致不意味着算力一致。为基线、确认性评价及审计预留预算，不能用搜索把它们耗尽。

**人工门 G3**：未填写字段、未实现评分器、未核验数据或未得到批准，均阻止正式执行。协议改动生成新版本，说明原因、已看过哪些数据、哪些分析降为探索性；不得覆盖旧记录。

## 4. 基线先行，再做受限实验

1. 在隔离开发环境复现基线，确认指标计算、数据切分与预算统计正确。
2. 使用极小的冒烟测试验证输入输出；不能把冒烟测试称为基准完成。
3. 一个实验回答一个主要问题。记录父实验、假设、代码差异、计划版本、配置及预期结果。
4. 每次尝试追加 `runs.jsonl` 记录，包括失败、取消、超时、无收益和完整性异常；不得从分母中删除。
5. 保留原始输出和日志，再运行固定分析；图表和报告只能从已保存数据生成。
6. 异常重试只遵循预注册策略：重试有新 run ID，链接原尝试，累计消耗不归零。
7. 保留候选或回滚代码时写明依据。代码回滚不删除历史尝试和负结果。

**执行成功 ≠ 假设成立。** 进程完成只说明软件终止正常；指标通过只说明特定测试结果；科学主张还需要边界、比较和审计。

## 5. 消融、多种子与不确定性

- **重复单位先于统计**：区分样本、任务、数据集、训练种子和 Agent 完整运行。共享训练模型下的几千个测试样本不能冒充几千次独立训练。
- **成对比较**：能配对时采用同一数据划分、任务与种子。报告每对差值及总体效应，说明配对合理性。
- **多种子**：数量由方差、成本和检测阈值决定。三次或五次不是通用保证；小样本需明确区间不稳定。
- **不确定性**：按预定独立单位计算置信区间或其他明确说明的区间。报告方法、覆盖对象和假设；种子间区间通常不覆盖数据分布变化。
- **消融**：移除新增组件、匹配参数/算力、加入简单替代；性能消融不能自动证明某个因果机制。
- **多重尝试**：同时公开搜索次数和选择规则。开发集上选出的最好值不能当无偏的最终效果。
- **负结果分类**：不支持、与实用零效应相容、区间太宽而不确定、实验无效、资源不足。未显著不等于等效，运行失败不等于科学反证。

**人工门 G4**：检查完整性、可比性、原始记录、分析忠实度与最强替代解释。出现泄漏或评分器被修改时隔离相关结果，不用它们支持主张。

## 6. 从证据到声明，再到写作

`claims.md` 是所有摘要、图注、结论和对外材料的共同账本。每条声明具有 ID、准确措辞、状态、支持与反对证据、分析文件、适用条件、复核人和日期。

建议状态：`proposed`、`supported`、`not_supported`、`inconclusive`、`invalidated`。未执行的示例只能是 `proposed`，不能填写示意性“结果”。

写作顺序：先结果表与证据链接，再限制和替代解释，再讨论，最后摘要。每个定量数字能追溯到原始结果和生成步骤；每个引用确实支持附近的句子。不要把模型预测、合成数据、模拟结果、作者宣称或复核意见写成真实实验观测。

**人工门 G5**：逐条核对主张；完成[复现检查表](../templates/project/reproducibility.md)、数据/许可审查和敏感信息检查后，由负责人决定是否公开。自动写作和自动审稿不是发表授权，也不是独立科学验证。

## 7. 反思与有门槛的经验沉淀

复盘写入 `reflection.md`，区分观测、候选解释、可区分它们的下一步实验和决策。至少比较两个合理解释；证据不足时保留未知，避免把顺畅的叙事当诊断。

经验先进入 `memory.md` 的 `candidate` 区，满足以下条件才可转为 `admitted`：

1. 有准确的来源、run ID/claim ID、适用条件和不确定性。
2. 无数据泄漏、未解决完整性异常或依赖未读来源。
3. 已检查反例；一次局部失败只存为局部观察。
4. 若要推广为通用方法建议，已有额外独立证据或明确标为待验证启发式。
5. 复核者批准适用范围与复查日期；未来冲突可降级为 `contested` 或 `retired`。

经验只能帮助提出下一轮假设，不能悄悄改动冻结评分器、预算、测试访问策略或安全边界。改变研究策略本身也要在单独开发任务上比较，不能用本轮最终测试选择“更好的反思提示词”。

## 每轮最小交付包

- 问题、检索日志、创新矩阵和反证条件
- 冻结计划及人工决策记录
- 全部尝试、失败原因、成本和原始证据索引
- 主结果、消融、不确定性与负结果
- 声明—证据账本、复现说明、边界与未解决问题
- 下一轮最有信息量的动作，或有理由地停止
