# 原生 DSH 会话续接验证（2026-10-18）

原版 CORAL 固定提交的 DeepSeek 适配器没有提取或传递会话 ID；实际安装的官方 DSH `0.2.0-rc.2` 已支持恢复。SAGE 的修复通过公开自定义运行器接口使用真实原生 ID，不改动固定上游源码，不修改评分标准或此前科学产物。

## 真实运行核对

AutoDL 上的独立软件验收使用 `deepseek-flash`，原生请求记录仍为 1,000,000-token 上下文。随机标识只在测试对话中提供，期望值保存在管理器私有文件，不放入代理工作区或续跑提示词中。

- 正常退出后，用原生 ID 恢复，并准确回忆前一段对话的随机标识。
- 在真实 shell 工具执行 `sleep` 期间，调用原始 CORAL `AgentManager._interrupt_and_resume`。SIGINT 后恢复同一 ID，准确回忆打断前的两个标识，并接收到新反馈标识。
- 重建运行器且不传 ID，依据管理器私有、绑定 agent 与绝对目录的指针恢复同一会话，继续准确回忆全部标识。此项验证运行器的状态恢复路径，未声称实际重启整个 CORAL 管理器进程。
- 在新的 Python 进程中再次读取私有指针，恢复同一 ID，准确回忆全部标识。此项仍是运行器恢复验收，没有实际重启完整 CORAL 管理器。
- 原生持久化序列从 33 条增长至 59 条、70 条、81 条；同一 ID，历史用户消息与新增反馈均保留。
- 不一致 ID 在启动前被拒绝；合法格式但不存在的 ID 由原生 DSH 拒绝，没有新会话回退。
- 投影日志没有 `thinking` 或完整工具参数、结果；原生会话文件不发布。

此 fixture 的 15 项记录检查通过。此前两个启动检查因两层 CLI 的参数顺序不正确而失败，已保留；修正为所有全局 `--patch` 位于 headless `--json` 之前后才完成上述验收。失败检查没有被当作科研运行成功。

完整离线检查在 Windows 和 AutoDL Linux 均通过：460 项（Windows 跳过 1 项实际 Unix 权限检查；Linux 全部执行）。新增 26 项覆盖原生参数顺序、真实 ID 提取、冲突/损坏状态拒绝、所有者和权限、符号链接与日志过滤。离线检查不调用模型，不能替代上述真实续接验收。

## 评分影响的证据边界

此前真实猜想运行中，重开会话后既有 0.62→0.74，也有 0.74→0.58；不同评分对应不同稿件。评分服务每次都单独发送完整对应稿件与文献证据，未依赖研究代理的会话 ID。最后一版仍保留多项早期修复，但又受到识别、可行性和统计设计方面的批评。

因此不能从现有记录认定 warning 导致降分，也没有估计同稿评审波动。当前修复验证会话身份、历史和反馈的连续性，未证明科研质量提高或猜想成立。严格质量对照仍需从同一冻结检查点出发，控制初始材料、模型和预算后比较。
