# 架构：文件化研究控制面

## 定位与实现边界

本仓库选择可阅读、可复制、可版本化的文件作为研究状态，而不是绑定某个 Agent 框架。Markdown 承载论证与人工判断，JSON 承载计划，JSONL 承载逐次尝试。Python 辅助脚本的实际能力以根目录 README 为准。

**已提供**：工作流规范、项目模板、未执行的计划示例，以及仓库中实际存在的辅助工具。

**设计中的契约**：检索、实验执行、隔离评价、制品保存与记忆适配器的输入输出。

**尚未提供**：可信身份验证、签名审批、并发锁、OS/容器级沙箱、强制预算、远程队列、真实模型后端、自动训练、可靠的最终测试隔离。JSON 中写 `approved` 或 `network: false` 不会自动实现授权或断网；接入执行器前必须另行实现和验证。

## 三类权威，不能混淆

| 层 | 权威与职责 | 不能做什么 |
|---|---|---|
| 研究控制面 | 负责人确定问题、预算和评价契约；保存版本、证据与决策 | 不能因自然语言“建议”自动扩大权限 |
| 执行与评价面 | 受限执行器运行批准的配置，独立评价器产出原始指标 | 不能自行更改主指标、改写过去结果或批准自己 |
| 外部知识面 | 论文、代码、网页、工具输出提供候选信息 | 不能指挥执行器、修改政策或索取秘密 |

同一模型扮演多个角色不构成独立复核；同一操作系统账号可写全部文件也不构成权限隔离。初版靠人工审查，生产接入必须使用真实的读写权限和身份边界。

## 项目目录约定

项目根目录下保存以下文件；模板位于 [templates/project](../templates/project/)。

```text
brief.md                 问题、范围、责任、权限与停止条件
literature.md            检索日志、来源卡片与证据定位
hypotheses.md            创新矩阵、假设、替代解释与反证
preregistration.json     实验前冻结的结构化计划
benchmark.md             基准选择、版本、污染与可比性检查
decisions.md             人工门禁、计划变更与公开决定
runs.jsonl               每行一条尝试记录；初始为空
claims.md                声明、支持/反对证据与状态
reflection.md            观测、竞争解释与下一步
memory.md                候选、采纳、争议、退役经验
reproducibility.md       环境、数据、制品与复核清单
```

实际运行后由接入者添加 `artifacts/<run-id>/`，包含配置、代码差异、环境清单、标准输出、错误、指标和校验和。不要把私有数据、API 密钥、账号令牌或版权受限全文提交到公开仓库；大制品放在授权存储，仅记录可访问位置、哈希和访问条件。

所有对象有稳定 ID，例如 `SRC-001`、`H-001`、`PLAN-001-v1`、`RUN-001`、`CLM-001`、`DEC-001`。时间使用带时区的 ISO 8601；预算单位显式，金额带币种。`null` 表示未填或未知，不能解释为零、无限或已批准。

## 状态转换与人工门

建议项目状态为 `draft → evidence_ready → preregistered → executing → auditing → reported → archived`；任意阶段可进入 `blocked`。这些是流程约定，当前不由文件编辑自动强制执行。

- `draft → evidence_ready`：G0/G1/G2 通过，问题、证据和反证足够清晰。
- `evidence_ready → preregistered`：G3 批准精确计划版本；评分器与数据版本可核验。
- `preregistered → executing`：实际执行器确认权限、资源、隔离和余额。
- `executing → auditing`：计划完成或触发预定停止条件；全部尝试都有记录。
- `auditing → reported`：G4/G5 通过；不支持与不确定也可形成完整报告。
- 任何冻结项变更：保留旧版本，新增决策和计划；已知测试信息不能“忘掉”。

## 适配器契约草案 v0

这些是接口设计说明，**不是已经可调用的 API**。适配器只处理结构化数据，不解释外部文本中的命令；命令执行入口只允许负责人审查过的代码和明确参数。

### 1. 文献检索适配器

输入：研究问题、查询、时间范围、来源域名/集合、最大条目数与费用上限。

输出：来源 ID、原始链接、版本、访问时间、题录、获取状态、内容哈希、可定位片段及已读范围。片段与“研究者推断”分字段。无法获取/验证时返回原因，不生成伪引用。检索响应不得携带可直接执行的 shell 字段。

### 2. 执行适配器

输入：批准的计划 ID/文件哈希、run ID、父 run ID、审查过的代码提交、数据指纹、明确配置、种子、环境标识及预算配额。

前置检查：审批身份与范围有效；代码/数据/评分器匹配；实际沙箱可用；总余额足够；路径规范化后在项目允许范围内；拒绝 `..` 越界和指向边界外的符号链接。默认拒绝未经允许的网络、子进程、安装和外传。

输出：`run-record.json` 风格的记录、原始日志和制品清单。记录真实状态、开始/结束时间、退出码、实际消耗、配置与代码身份。执行器不能把缺失指标填成 0，不能把仿真预测写成测量。

幂等与失败：相同 run ID 重复提交应查询原任务，不能默认启动第二份；重试使用新 ID 并关联原 ID。部分产物标记未完成，原错误不得覆盖。强制预算需要执行器计量与终止机制，字段本身无强制力。

### 3. 评价适配器

输入：候选制品、冻结评价器/数据指纹、预定种子与聚合规则。最终评价器只接收冻结候选，不接收能够覆盖标签、评分器或运行命令的任意文本。

输出：逐单位原始分数、聚合分数、失败/缺失、消耗与评价器版本。开发指标与最终确认性指标分开。开发者对最终测试的读取应由另一权限域控制；每次测试访问登记。

完整性异常返回 `invalid` 并隔离结果。评价失败不触发“换一个更好看的指标”；先诊断，再按原协议重试或登记偏离。

### 4. 证据与制品适配器

输入：已完成或已终止的尝试记录及制品路径。

输出：内容哈希、类型、大小、产生者、来源 run ID、存储位置、访问限制。写入采用临时文件与原子替换；账本采用单写入者或数据库事务，避免并发覆盖。生产实现还需备份、访问日志与篡改检测。

SHA-256 可检测与已知值不一致，不能证明文件真实、作者可信或统计结论正确。Git 版本历史可辅助审查，不是审计系统的完整替代。

### 5. 反思与经验适配器

输入：原始运行结果、已审查声明、冲突与历史失败。

输出：观测、至少两个候选解释、辨别性实验、局部经验候选、范围、证据和失效条件。经验采纳需要人工记录；适配器无权改写历史或放宽批准边界。

## 并行、恢复与可移植性

- 每个实验独占工作目录和 run ID，避免多个 Agent 写同一训练文件。
- 分配预算时保留全局上限；并发子任务不能各自获得完整预算。
- 重新启动从文件和制品重建状态，先确认远端任务是否仍运行，防止重复付费。
- 原始记录追加，派生汇总可重建；更正用新记录说明替代关系，不静默修订原始值。
- 从一个后端迁移到另一个后端时保留 ID、单位、版本与错误语义；任何无法映射字段都显式报告。

## 最小接入验收

新适配器上线前至少测试：未审批拒绝、计划哈希不符拒绝、预算耗尽停止、重复提交不双跑、路径越界拒绝、含恶意指令的论文只当数据、评价器不可写、失败保留、日志不含秘密、断点恢复、原始指标可重算。隔离或授权测试不能通过时只保留人工使用模式。
