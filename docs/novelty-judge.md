# 新颖性裁判与改进建议

目标是让研究者得到可核查、可反驳、能指导下一步的评阅。分数只是其中一项产物。新颖性必须说明“相对哪项工作、在哪些条件下、多出了什么科学内容”；讨论人数、措辞长度和组件数量不构成创新证据。

## 已接入的第一版

原生 `ResearchService.judgment` 执行两个有界、无会话历史的评阅阶段，使用同一份冻结科学输入和证据快照：

1. **原七维评分**：继续使用 ARIS research-refine 的问题忠实度、方法具体性、贡献质量、前沿利用、可行性、验证聚焦、投稿潜力及原权重。程序计算总分，不向评阅者暴露作者自评、历史分数或调用者 focus。
2. **不看分数的新颖性与建议审查**：读取原 proposal、实际证据及待核查建议，拆出科学主张，核查最近工作比较，分别判断每条批评和修复建议，并提出可选的新颖性改进动作。第一步的分数、等级和存活名单不会通过评语账本传给第二步。

实现位于 [review.py](../sage/autonomous/review.py)、[novelty.py](../sage/autonomous/novelty.py) 和 [service.py](../sage/autonomous/service.py)。数字量表版本和反馈契约版本分别记录；新反馈不修改原权重、覆盖原分数或宣称不同版本的得分可直接比较。

2026-10-18 第一版每阶段一次请求；2026-10-19 的[可靠性修复](autonomous-reliability.md)增加显式、留痕的阶段内格式修复。当前默认每阶段最多一次修复，因此正常两个请求、上限四个；嵌入式配置 `review_repair_attempts` 支持 0–2，上限公式为 `2 × (1 + review_repair_attempts)`。合法数值评级冻结，只重做失败阶段；额外请求消耗预算，失败不静默重开整轮。实际调用模型、各阶段用量、请求、原始失败回复及输入/证据哈希分别保存。新请求仍使用已配置的 API；同一模型的新上下文不是独立模型家族。第二步失败不能留下完整评阅成功收据，第一步原始输出和部分结果仍保留。2026-10-20 起，校验失败除原一句话文案外还回显 ID 级结构化 detail（非法引用/ID 列表与该候选允许子表，不含论文原文），随修复后缀和失败收据一并给模型与调用方；detail 只作参考数据、按不可信 DATA 对待，各校验门仍全量重验、强度不变。

2026-10-21 起评审 prompt 采用投影瘦身（模型侧紧凑视图、宿主侧全量保留）。第一阶段 `RETRIEVED EVIDENCE` 不再原样序列化整个 evidence store，改为确定性紧凑证据视图 `evidence_view`：按 paper 给出 title、abstract（≤800 字符，超出截断加省略标记）、claims 按类别分组（九个主类别 problem/motivation/method/assumptions/metrics/results/limitations/reproducibility/future_work；capsule 额外的 data/baselines 两类保留独立分组而非丢弃；每类 ≤6 条、每条 ≤300 字符）、未验证 inferences、阅读范围摘要与 targeted passage 块 ID 清单；span 只以 ID 出现在 claims 的 source_span_ids，原文永不进 prompt；searches 一行式 `{query, purpose, 结果数}`。体积目标：该段 ≤400KB（构造证据 fixture 的回归测试断言，实测 fixture 全量 706KB → 视图约 23KB）。第二阶段 `AUTHENTICATED REFERENCE CATALOG` 索引化：只对每个候选 `closest_prior_art` 指向的最近 1–2 篇 source 保留 span 原文全文（句级比对与引用需要），其余 in-scope source 只给 claims 紧凑摘要 + reference ID 清单；候选没有任何 closest_prior_art 时全部 source 走摘要模式。`ALLOWED REFERENCE IDS BY CANDIDATE` 表照旧全量，宿主侧 `_reference_catalog(evidence)` 不变（仍全量）。门的强度论证：两段校验（`validate_review`/`validate_feedback`）零改动、错误文案不变；校验所需的 scope、全量 catalog 与原文都在宿主侧冻结证据里，引用由程序查表并复制原文（`manager_source_lookup_not_entailment`），模型看不看得到 span 原文不影响任何门的判定——对模型从未以原文形式看到的 source 引用 reference ID，宿主照样解析通过（回归测试 `test_host_gate_resolves_references_hidden_from_the_model_view` 断言）。投影全部确定性实现、不调模型；宿主 evidence store、catalog 构建与请求留痕（`evidence_sha256` 等）不变。

### 主张与证据

每个入选候选至少拆出一条方法、发现或评价主张。每条记录最近来源、重合部分、实质差异、证据限制，并给出以下判断之一：

| 状态 | 含义 |
| --- | --- |
| `covered` | 评阅者认为给定最近工作已覆盖这条具体主张；必须定位到实际来源文本，不能仅凭邻近主题判死刑。 |
| `distinct_within_evidence` | 评阅者认为与当前提供的证据存在明确差异；必须给出来源定位和差异解释，仍不等于全面查新通过。 |
| `unknown` | 当前检索、阅读或比较不足；必须保留缺口。没有检索到不等于不存在。 |

来源定位只能引用管理器持有的证据卡原文切片或已读取原文段落。模型返回来源与引用 ID，程序从冻结证据中复制原文，不采纳模型另写的“引文”。外来论文 ID、伪造引用位置和无原文支撑的确定性状态被拒绝。原文位置核对只证明引用存在，语义支持关系仍是待复核的模型判断；摘要与部分全文的阅读范围不得升级成完整方法核验。

### 批评与修复分别核查

建议账本覆盖原评阅的所有 issue 和已填写的逐维 concrete_fix。每项输出两套判断和各自理由：

- 问题：`supported / disputed / unknown`。
- 修复：`helpful / harmful / unknown`。

例如，样本量推导可能确有问题，但“按处理后变量重新匹配”的修复可能破坏目标因果效应。不能因为前半句正确就接受整条建议。遇到被反驳的批评或有害修复，程序标记 `requires_adjudication`；它不自动决定哪位模型正确，也不静默改分。研究者应根据原文、推导或实际数值检查裁决，保留拒绝意见的理由。

原评阅的泛化 simplification/modernization 文本不在这份逐条核查账本中，仍是未验证机会，不能拿来作为已接受修复。新提出的改进动作也不会由提出它的模型自动批准。

### 面向新颖性提升的建议

每个候选可没有建议，也可给出少量有科学依据的动作。每条明确：目标主张、具体机制变化、预期科学增量、区分新旧解释的测试、证伪条件、成本与风险，以及下一步查新的查询词。

可行的方向包括：放松一个关键假设；发现方法失效的边界；推导可检验条件或反例；用更小机制解释同一现象；排除已有解释后建立新测量或新规律。将已知组件组合起来也可能有价值，但需要检验组合产生的新预测。改名、堆模块、跟随热门模型或单纯多做实验不能自动提高新颖性。

这些动作统一为 `proposed_unverified`。建议中的查询没有执行，预测没有被实验证实。研究者使用真实 search/read 工具查找相同机制、同义表述、最近方法和反证；修改完整科学方案，保留旧稿，再对新文件进行新的评阅。新的证据和哈希形成下一轮记录。此流程由原生工作流指令衔接，不能将自然语言指令视为所有行为已经被程序强制证明。

## 提示词要求

以下是含义等价的中文说明；运行时英文提示词、精确响应契约和验证代码以 `review_prompt`、`feedback_prompt` 为准，请求原文也保存到每轮私有审计目录。

**评分者**：只评给定入选方案，与管理器冻结的问题对照；不读作者历史分数。核查机制、假设、数学统计、因果识别、最近工作、资源和证伪。七维低于 7 分须给弱点、方法级修复及优先级。缺证据不能当作已证新颖，也不要强迫添加热门组件。由程序汇总，当前无人工标定，不给发表概率。

**建议核查者**：你看不到分数，不负责抬分。逐条检查批评是否成立、修复是否正确，两者分别判断并解释。支持批评不要求支持其修复。方法逻辑问题可用明确推导，关于文献的判断只使用实际来源，未知就保持未知。

**新颖性教练**：指出当前主张与最近工作之间的具体关系。只有在有依据时才提出改进；每项须说明改变哪个机制或条件、增加什么可检验科学内容、什么结果会否定它、最小区分试验和代价。检查是否只是已知方法重述、无必要的复杂化或问题漂移。新建议保持待验证，不声称已搜索、已实现或已提高创新性。

完整运行提示词将后两个职责合并在第二个评阅阶段中。阶段内修复不会增加独立裁判人数；新建议在下一版真实方案的检索与评阅中受检。这一范围不能宣传为完整的多家族盲评系统。

## 吸收四个来源的哪些优点

| 来源 | 借鉴内容 | 保留的边界 |
| --- | --- | --- |
| ARIS | 七维具体问题、方法级修复、问题锚点、最近工作查新、克制的简化建议。 | 无人工精选参考例就不声称标定完成；API 单家族不满足其原独立验收条件。 |
| CoI | 文献驱动的建议，促进新颖性与可行性，同时控制不必要复杂度。 | 原成对排序不能单独证明科学正确；空检索不支持创新结论。 |
| Agent Laboratory | 分别关注新颖性、实验解释和领域贡献的评阅视角。 | 未做实验的 idea 不套用成稿量表；评阅者自报信心不加到质量分里。 |
| CORAL | 版本冻结、实际产物与收据、固定标准、本地可重复汇总。 | 通用任务示例的 PASS/FAIL 不是现成科研量表；修订前后不临时改标准。 |

原始代码、量表和实际接线对照见 [upstream-review-rubrics.md](upstream-review-rubrics.md)。新模块是 SAGE 的集成改造，不是上游原样具备这整个组合。

## 建议继续做的第二版：尚未实现

1. **有来源的人工参考集**：按领域挑选已有工作重述、可靠增量、设计失效、有效新发现等案例。分开用于校准和留出评测；不能由当前生成者自己挑选有利参照。先校准量表、误杀和漏判，再决定是否改权重。
2. **修订前后盲评**：把两个版本匿名、交换展示顺序，在相同证据快照下比较科学增量和回归风险，允许平局和弃判。随后单独报告新增证据导致的判断变化，避免将查到新论文造成的降分误解为修订变差。尚未实现交换顺序和成对裁决代码。
3. **专业复核与可执行检查**：将信息论、统计、因果、系统预算等有争议问题交给针对性核查；能够确定性检验的公式、有限反例和成本算式用代码验算。模型投票不能替代这类证据。
4. **真实效果对照**：固定方向、初稿、证据和调用预算，比较原七维、加建议核查、再加新颖性改进三个版本。由看不到组别的评阅者复核有效改进率、有害修复率、漏掉最近工作的比例、保留可行性及成本。只报告真实测量，不预设必然提升。

“换顺序、隔离历史分数、控制文字长度影响”用于降低可控偏差。已有研究报告了位置、冗长和自偏好问题：[MT-Bench / Chatbot Arena](https://arxiv.org/abs/2306.05685)。关于仅凭模型内部反馈反复修订的局限，可参见 [Large Language Models Cannot Self-Correct Reasoning Yet](https://arxiv.org/abs/2310.01798)；该论文的推理任务结论不能直接当作本系统科研质量的实测结果。

## 验证范围

合成回归测试检验来源/引用 ID、判断状态、建议覆盖、结构失败、计分隔离及真实服务接线；它们不证明模型的批评、新颖性结论或修复建议在科学上正确。本轮没有重跑付费模型、没有修改历史科学产物，也没有用新契约重新解释历史分数。真实质量提升需要上面的受控比较和人工复核。
